# Security Policy

## Supported Versions

boltforge is currently pre-1.0. Security fixes are made against the
latest published version on [pub.dev](https://pub.dev/packages/boltforge).
There is no separate long-term-support branch at this stage.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |

## Reporting a Vulnerability

**Please do not open a public GitHub issue for a security vulnerability.**

Instead, email **alihabibadministrator@gmail.com** with:

- A description of the vulnerability and its potential impact.
- Steps to reproduce it (a minimal `boltforge create`/`boltforge generate`
  command sequence, if applicable).
- Your assessment of severity, if you have one.

You should expect an acknowledgment within a few days. If the issue is
confirmed, a fix will be prioritized and a new version published; you'll
be credited in the release notes unless you'd prefer otherwise.

## Scope Notes

boltforge is a code generator: it writes files to disk and shells out to
`flutter`/`dart`. Relevant classes of issues include (but aren't limited
to):

- Path traversal or unsafe file writes during project/feature generation.
- Unsafe modification of `lib/core/di/service_locator.dart` (the
  `DiRegistrar` marker-based insertion) that could corrupt or inject into
  a file beyond the intended lines.
- Command injection via arguments passed to `Process.run` in
  `ProcessService`.

Issues in a project *generated by* boltforge that stem from the
developer's own backend configuration (e.g. an unset `ApiConstants.baseUrl`)
are outside this policy's scope — those are ordinary application bugs to
fix in the generated project itself.
