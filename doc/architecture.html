المعمارية العامة

يوجد نظامان معماريان منفصلان في هذا المشروع: معمارية أداة boltforge نفسها (Dart CLI)، ومعمارية المشروع المُولَّد (تطبيق Flutter). هذه الصفحة تشرح كليهما.

ماذا تفعل هذه الطبقة؟

معمارية الأداة تفصل بين: تحليل الأوامر (commands)، تنسيق العملية (generators)، التعامل مع النظام الخارجي (services)، وتوليد الملفات من القوالب (template_engine). هذا الفصل هو ما يجعل الكود قابلًا للاختبار بدون Flutter/Dart حقيقي مثبَّت (انظر صفحة الاختبارات).

لماذا صُمِّمت بهذا الشكل؟

لو كانت كل أوامر flutter create وflutter analyze مكتوبة مباشرة داخل CreateCommand، لاستحال اختبار منطق الأداة بدون تثبيت Flutter فعليًا. لذلك كل استدعاء لعملية خارجية يمر عبر ProcessService (واجهة رفيعة قابلة للاستبدال باختبار وهمي FakeProcessService).

القاعدة الذهبية: من يُسجَّل في GetIt؟

💡 قاعدة معمارية صارمة

فقط الـ Repositories تُسجَّل في sl (GetIt) كـ lazy singleton. الـ Cubits لا تُسجَّل أبدًا — تُنشأ محليًا داخل كل شاشة عبر BlocProvider(create: (_) => XxxCubit(sl())). هذا موجود في تعليق داخل service_locator.dart.tmpl نفسه.

💡 هذا التسجيل يحدث تلقائيًا الآن

منذ إضافة DiRegistrar، عند تشغيل boltforge generate offer تُضاف import الـ Repository الجديدة وسطر sl.registerLazySingleton<OfferRepository>(...) تلقائيًا إلى service_locator.dart — بدون أي تعديل يدوي. التفاصيل الكاملة (كيف تعمل الآلية، وماذا يحدث إن كان الملف معدَّلًا يدويًا) في صفحة توليد الـ Feature.

كيف تُعدّل هذه المعمارية؟

  • لإضافة تبعية جديدة لكل مشروع مُولَّد: عدّل قائمة requiredPackages في project_generator.dart.
  • لتغيير شكل الأخطاء القادمة من الـ API: عدّل ApiError في templates/base/lib/core/network/api_error.dart.tmpl.
  • لإضافة معترض Dio جديد (Interceptor): أنشئ ملفًا جديدًا بجانب token_interceptor.dart.tmpl وأضفه في dio_client.dart.tmpl.
  • لتغيير آلية التسجيل التلقائي في GetIt: عدّل lib/src/services/di_registrar.dart (تعتمد على تعليقَي الترسيخ // boltforge:imports و// boltforge:registrations الموجودَين في service_locator.dart.tmpl — لا تحذفهما).

أخطاء شائعة

الخطألماذا يحدث
تسجيل Cubit داخل service_locatorيكسر مبدأ إنشاء Cubit لكل شاشة، ويسبب تسرّب حالة بين الشاشات.
استدعاء sl() داخل build() مباشرةيجب استدعاؤه داخل BlocProvider.create فقط، وليس أثناء إعادة البناء.
حذف تعليقَي // boltforge:imports/// boltforge:registrations يدويًايوقف التسجيل التلقائي بالكامل لأي Feature قادمة — الأداة سترصد غيابهما وتحذّرك بدل التخمين بمكان الإدراج.

معايير القبول

  • لا يوجد أي Cubit مسجَّل داخل configureDependencies().
  • كل Repository في lib/features/*/repository/ يستخدم DioClient.instance.dio فقط، ولا يبني عميل Dio خاصًا به.
  • كل خطأ شبكة يمر عبر ApiError.fromDio ولا يصل كـ DioException خام إلى الواجهة.
  • كل Repository مولَّدة عبر generate مسجَّلة في service_locator.dart مرة واحدة بالضبط.
