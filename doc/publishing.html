✔ Phase 3 مكتملة — لم يبقَ سوى النشر الفعلي

LICENSE, CHANGELOG.md, CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md, و.gitignore كلها موجودة الآن. dart analyze نظيف وdart test ناجح بالكامل فعليًا (تحقّق حقيقي على جهاز المطوّر، وليس فقط تتبعًا يدويًا). ما تبقّى: تشغيل dart pub publish --dry-run فعليًا وتحليل نتيجته — راجع project-dashboard.html لحالة كل عنصر تحديدًا.

ماذا يعني "النشر" هنا؟

رفع حزمة boltforge إلى pub.dev بحيث يستطيع أي مطوّر تثبيتها عالميًا بأمر واحد: 

dart pub global activate boltforge

لماذا لم يحدث النشر الفعلي بعد؟

لأن النشر على pub.dev شبه نهائي (لا يمكن حذف إصدار منشور، فقط "تقاعده" retract). القرار الفني (تحقّق حقيقي من الاختبارات، ترخيص واضح، توثيق كامل) اكتمل بالفعل — ما تبقّى هو تشغيل --dry-run فعليًا وقرار نهائي واعٍ من صاحب المشروع بالضغط على زر لا رجعة فيه سهلة.

المتطلبات قبل النشر (checklist)

  • ✔ تشغيل حقيقي لـ dart format . && dart analyze && dart test بدون أي فشل — تم فعليًا.
  • وجود LICENSE فعلي في جذر المشروع — ✔ تم (MIT).
  • وجود CHANGELOG.md يوثّق أول إصدار (0.1.0) — ✔ تم.
  • pubspec.yaml يحتوي homepage/repository تشير إلى github.com/alihossainhabib/boltforge — ✔ تم كتابتها؛ يبقى إنشاء المستودع فعليًا على GitHub بهذا الاسم (لم يُفترض وجوده، فقط جُهِّزت الروابط له).
  • التحقق من توفّر الاسم boltforge فعليًا على pub.dev — لم يُتحقَّق منه بعد، وdart pub publish --dry-run سيكشف هذا مباشرة إن كان الاسم مأخوذًا.
  • تجربة محاكاة النشر (--dry-run) قبل أي رفع فعلي — الخطوة التالية المباشرة.

الأمر التالي بالضبط

terminal
# محاكاة أولًا — لا يرفع شيئًا فعليًا، فقط يتحقق من كل المتطلبات
dart pub publish --dry-run

# فقط بعد مراجعة نتيجة الأمر أعلاه والتأكد التام:
dart pub publish

كيف تتحقق من توفر الاسم بنفسك

ابحث يدويًا عبر https://pub.dev/packages/boltforge — إن ظهرت صفحة حزمة موجودة فعلًا، يلزم اختيار اسم بديل وتحديث pubspec.yaml وbin/ (اسم الحزمة يظهر في executables: ضمن pubspec.yaml) وكل الوثائق المرجعية له.

ماذا يتحقق منه --dry-run فعليًا؟

  • صحة بنية pubspec.yaml (الحقول الإلزامية: name, description, version, environment).
  • وجود ملف LICENSE.
  • حجم الحزمة (لا يتجاوز الحد الأقصى المسموح).
  • عدم وجود ملفات حساسة (مثل مفاتيح API) عبر آلية false_secrets في pubspec.yaml.
💡 ملاحظة على pubspec.yaml الحالي

الحقل false_secrets: - "/templates/**" موجود مسبقًا في pubspec.yaml ليخبر أداة تحليل pub.dev أن محتوى مجلد templates/ (رغم احتوائه نصوصًا تبدو كأكواد حساسة أحيانًا) ليس سرًّا فعليًا، بل قوالب توليد عادية.

معايير القبول

  • dart pub publish --dry-run يمر بدون أي تحذير أو خطأ — لم يُختبَر فعليًا بعد، هذا التالي بالضبط.
  • اسم الحزمة مؤكَّد التوفر فعليًا على pub.dev قبل أول نشر.
  • يوجد وسم Git (tag) مطابق لرقم الإصدار في pubspec.yaml وقت النشر.
