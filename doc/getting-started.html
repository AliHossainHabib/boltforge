البدء السريع

تثبيت الأداة، وإنشاء أول مشروع، خطوة بخطوة.

ما الهدف من هذه الصفحة؟

توصيل أي مطوّر Flutter من "لا شيء مثبَّت" إلى "لدي مشروع يعمل بمعمارية جاهزة" في أقل عدد ممكن من الخطوات، مع توضيح ماذا يحدث فعليًا في كل خطوة بدل حفظها كصندوق أسود.

لماذا توجد هذه الخطوة (التثبيت)؟

boltforge حزمة Dart قابلة للتفعيل عالميًا (global activation) مثل أي أداة CLI أخرى في نظام Dart البيئي (مثل dart_frog أو mason). هذا يعني أنها تُثبَّت مرة واحدة وتصبح متاحة كأمر boltforge في أي مجلد.

المتطلبات

  • Flutter SDK مثبّت ومُتاح في PATH (flutter --version يعمل).
  • Dart SDK (يأتي مع Flutter تلقائيًا).
  • اتصال إنترنت عند إنشاء مشروع جديد (لأجل flutter pub add).

الأمر بالضبط

terminal
dart pub global activate boltforge
⚠ ملاحظة صريحة

هذا الأمر يفترض أن الحزمة منشورة فعليًا على pub.dev. في الوضع الحالي (Phase 1) لم يتم النشر بعد — راجع صفحة النشر. للتجربة الآن محليًا، استخدم بدلًا من ذلك: 

cd boltforge
dart pub global activate --source path .

الناتج المتوقع

Activated boltforge 0.1.0.

وإن لم يكن مجلد ~/.pub-cache/bin ضمن PATH، سيطبع Dart تحذيرًا يطلب إضافته — نفّذ ما يطلبه بالضبط قبل المتابعة.

التحقق من التثبيت

terminal
boltforge doctor

الناتج المتوقع عند سلامة البيئة (الكود في lib/src/commands/doctor_command.dart):

boltforge doctor

boltforge 0.1.0
  ✔ Dart SDK found: Dart SDK version: 3.x.x ...
  ✔ Flutter found: Flutter 3.x.x • channel stable • ...

Everything is set up. You are ready to run `boltforge create`.

إنشاء أول مشروع

terminal
boltforge create my_app --auth=password

إن حذفت --auth، ستسألك الأداة تفاعليًا (الكود في lib/src/commands/create_command.dart، الدالة _defaultPromptAuthChoice): 

Does authentication use a password?
  [1] Yes — email/phone + password, with forgot-password
  [2] No  — email/phone verification only (OTP-style)

كيف تتفاعل المكوّنات هنا؟

CreateCommand.run() يتحقق من الاسم عبر NameValidator، ثم يتأكد أن Flutter متاح عبر ProcessService.isAvailable، ثم يفوّض كل العمل الفعلي لـ ProjectGenerator.generate() الذي ينفّذ سبع خطوات بالترتيب ويتوقف عند أول خطوة فاشلة (راجع صفحة المعمارية للتفصيل الكامل).

أخطاء شائعة عند البدء

المشكلةالسببالحل
Exit code 69 Flutter غير موجود في PATH ثبّت Flutter وتأكد أن flutter --version يعمل، ثم أعد المحاولة.
Exit code 65 مجلد بنفس اسم المشروع موجود مسبقًا اختر اسمًا آخر أو احذف المجلد القديم يدويًا — الأداة لا تحذف شيئًا تلقائيًا.
Exit code 64 اسم المشروع غير صالح (أحرف كبيرة، شرطات، أرقام بالبداية...) استخدم lower_snake_case فقط، راجع صفحة إنشاء المشروع.

معايير القبول (Acceptance Criteria)

  • تشغيل boltforge doctor يعطي ✔ لكل من Dart وFlutter.
  • تشغيل boltforge create test_app ينتج مشروع Flutter صالح.
  • الأمر يتوقف صراحةً برسالة خطأ عند فشل أي خطوة، لا يدّعي النجاح أبدًا.
