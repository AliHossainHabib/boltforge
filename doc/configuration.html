الإعدادات (Configuration)

لا يوجد ملف إعدادات مركزي (مثل boltforge.yaml) في هذا الإصدار — هذه الصفحة توضّح أين تُضبط كل قيمة قابلة للتخصيص فعليًا، ولماذا لم نُضِف ملف إعدادات بعد.

لماذا لا يوجد ملف boltforge.yaml حتى الآن؟

لأن كل خيار حالي (نمط المصادقة، معرّف المؤسسة، تخطي التحقق) يُمرَّر بوضوح كعلامة سطر أوامر (--auth, --org, --skip-validation)، وهذا كافٍ للاستخدام الحالي. ملف إعدادات مركزي منطقي فقط عندما يتكرر تمرير نفس القيم في كل مرة عبر فريق كامل — وهذا قرار مؤجَّل عمدًا لمرحلة لاحقة (راجع PROJECT_STATE.json → known_issues).

أين تُضبط كل قيمة فعليًا الآن؟

الإعدادأين يُضبط
نمط المصادقةعلامة --auth عند create، أو السؤال التفاعلي
معرّف المؤسسة (Bundle ID)علامة --org (افتراضيًا com.example)
عنوان الـ Backendlib/core/constants/api_constants.dart بعد التوليد — الحقل baseUrl فارغ عمدًا
نقاط النهاية (Endpoints)بقية ثوابت ApiConstants في نفس الملف
الحزم المُضافة تلقائيًاقائمة requiredPackages في lib/src/generators/project_generator.dart — على مستوى الأداة نفسها، وليس لكل مشروع
الثيم/الألوانlib/core/theme/app_colors.dart وapp_theme.dart بعد التوليد

مثال كامل: ربط الـ Backend بعد التوليد

lib/core/constants/api_constants.dart (بعد create)
class ApiConstants {
  ApiConstants._();

  static const String baseUrl = ''; // ← ضع رابط الخادم هنا

  static const String login = '/auth/login';
  static const String register = '/auth/register';
  // ...
}

هذا هو الملف الوحيد الذي يحتاج تعديلًا يدويًا إجباريًا بعد كل create. كل من DioClient وكل Repository يعتمدان على هذه القيمة فقط، لذا تغييرها هنا يكفي لربط أي Backend (Node.js, Firebase, Laravel, Django, أو أي REST API).

كيف تتفاعل هذه القيم مع باقي الكود؟

DioClient.instance.init()
  → Dio(BaseOptions(baseUrl: ApiConstants.baseUrl, ...))
  → AuthRepository._dio = DioClient.instance.dio
  → AuthRepository.login() ينادي _dio.post(ApiConstants.login, ...)

كيف تُضيف ملف إعدادات مركزي بنفسك (اقتراح للتوسعة المستقبلية)

  1. أضف حزمة package:yaml (موجودة أصلًا كتبعية للأداة نفسها).
  2. اقرأ ملف boltforge.yaml اختياري من مجلد العمل الحالي في CreateCommand.run() قبل بناء TemplateContext.
  3. اجعل قيم مثل --org تُقرأ من الملف كافتراضي، مع بقاء علامة سطر الأوامر أعلى أولوية دائمًا (override).
  4. وثّق المفاتيح المدعومة في هذه الصفحة بالذات، وأضف اختبارًا في test/cli_commands_test.dart يتحقق من دمج الأولويات (CLI flag يتفوّق على ملف الإعداد).

أخطاء شائعة

الخطأالسبب
طلبات الشبكة تفشل بصمت أو بخطأ اتصال غامضنسيان ملء ApiConstants.baseUrl بعد إنشاء المشروع — القيمة الافتراضية فارغة عمدًا.
تغيير الثيم لا يظهرتأكد من تعديل AppTheme.light()/dark() وليس AppColors فقط إن كنت تستخدم ThemeData مخصص لا يعتمد على colorSchemeSeed.

معايير القبول

  • مشروع جديد يعمل بدون أي طلب شبكة فاشل بسبب baseUrl فارغ (يظهر خطأ واضح مُعالَج عبر ApiError، لا انهيار).
  • تغيير ApiConstants.baseUrl فقط كافٍ لربط backend جديد كليًا، بدون لمس أي ملف Repository.
