استكشاف الأخطاء وإصلاحها

دليل مرجعي لكل رسالة خطأ قد تراها، من أين تأتي بالضبط، وكيف تحلّها.

ماذا تغطي هذه الصفحة؟

كل رسالة خطأ في هذه الصفحة مرتبطة بسطر كود فعلي في المشروع — لا توجد رسالة "افتراضية" لم يُتحقَّق من مصدرها.

أخطاء boltforge create

Exit code 64 — اسم غير صالح

"123app" is not a valid project name. Use lower_snake_case: start with a
letter or underscore, then letters, digits, or underscores only
(e.g. "user_profile", not "123abc" or "user-profile").

المصدر: lib/src/validators/name_validator.dart، دالة validate.

الحل: استخدم lower_snake_case فقط: أحرف صغيرة، أرقام (غير بادئة)، وشرطة سفلية.

Exit code 65 — المجلد موجود مسبقًا

A directory named "my_app" already exists in /home/user/projects.
Choose a different name or remove it first — boltforge will not
overwrite an existing directory.

المصدر: lib/src/commands/create_command.dart.

الحل: غيّر الاسم، أو احذف المجلد القديم يدويًا بنفسك (الأداة لا تحذف تلقائيًا أبدًا).

Exit code 69 — Flutter غير موجود

Flutter was not found on PATH. Install Flutter and make sure
`flutter --version` works before running `boltforge create`.

المصدر: فحص process.isAvailable('flutter') في CreateCommand.

الحل: ثبّت Flutter، تحقق بـ flutter --version، ثم شغّل boltforge doctor للتأكيد.

Exit code 70 — "PathNotFoundException ...templates\base\*" أو "Could not locate boltforge's bundled templates/"

PathNotFoundException: Directory listing failed,
path = C:\Users\...\boltforge\.dart_tool\pub\bin\templates\base\*
(OS Error: The system cannot find the path specified., errno = 3)

السبب (خطأ حقيقي حدث فعليًا، وليس افتراضيًا): عند تفعيل الأداة عالميًا عبر dart pub global activate، تُنشئ Dart نسخة مُصرَّفة (snapshot) داخل .dart_tool/pub/bin/boltforge/ — أعمق بمستوى واحد من bin/boltforge.dart. الإصدار القديم من الأداة كان يفترض أن جذر الحزمة يقع دائمًا مستوى واحدًا فوق مكان تشغيل السكربت، وهذا الافتراض ينهار تحديدًا في هذا السيناريو — أي في الطريقة الحقيقية التي يشغّل بها المستخدمون الأداة فعليًا. تم إصلاح هذا جذريًا عبر الاعتماد على Isolate.resolvePackageUri بدل التخمين من مسار السكربت.

الحل: إن ظهرت هذه الرسالة رغم ذلك، تأكد أنك تستخدم إصدارًا محدَّثًا من boltforge (بعد هذا الإصلاح)، ثم أعد التفعيل: dart pub global activate boltforge (أو --source path . أثناء التطوير)، وشغّل boltforge doctor. إن استمرت المشكلة، فهذا يعني أن التثبيت نفسه ناقص وليس مجرد خطأ في تحديد المسار — أعد تفعيل الحزمة من الصفر.

توقف عند "flutter analyze"

المصدر: خطوة 6 من 7 في ProjectGenerator.generate(). هذه بوابة التحقق الرئيسية من صحة الكود المُولَّد.

💡 كيف تشخّص هذا بنفسك

الأداة تطبع مخرجات flutter analyze كاملة عند الفشل (الحقل detail في ProjectGenerationStepResult). اقرأ رسالة الخطأ بعناية — غالبًا استيراد مفقود أو نوع غير متطابق في أحد ملفات templates/ إن كنت قد عدّلتها بنفسك.

أخطاء boltforge generate

Exit code 65 — ليس مشروع Flutter

This command must be run inside a Flutter project.
No pubspec.yaml found in /home/user/some_folder.

المصدر: lib/src/services/project_detector.dart.

الحل: تأكد أنك داخل مجلد المشروع الجذري (حيث pubspec.yaml)، وليس داخل lib/ مثلًا.

مشاكل بعد التوليد (Runtime)

"StateError: StorageService.init() must be called..."

المصدر: lib/core/utils/storage_service.dart. يحدث إن استُدعيت أي دالة من StorageService قبل bootstrap().

الحل: تأكد أن main.dart ينادي await bootstrap() قبل runApp() — هذا هو السلوك الافتراضي المولَّد، فتحقق أنك لم تُعدّله بالخطأ.

طلبات الشبكة تفشل دائمًا فور التشغيل

السبب الأرجح: ApiConstants.baseUrl ما زال فارغًا (القيمة الافتراضية).

الحل: املأه في lib/core/constants/api_constants.dart — راجع صفحة الإعدادات.

Cubit لا يجد Repository عبر sl<T>()

Bad state: GetIt: Object/factory with type OfferRepository is not registered

السبب: منذ إضافة DiRegistrar، هذا لم يعد يحدث في المسار الطبيعي — boltforge generate يسجّل الـ Repository تلقائيًا. إن رأيت هذا الخطأ فعليًا، السبب على الأرجح أحد اثنين:

  • الأمر طبع تحذير DI: lib/core/di/service_locator.dart was not found أو DI: service_locator.dart is missing the marker comments — راجع مخرجات generate بعناية، فهو يخبرك بهذا صراحة وقت التوليد.
  • عدّلت service_locator.dart يدويًا وحذفت تعليقَي // boltforge:imports / // boltforge:registrations بدون قصد — في هذه الحالة الأداة تتوقف عمدًا عن التعديل التلقائي بدل التخمين.

الحل: أضف السطر يدويًا في configureDependencies() — الآلية الكاملة موضّحة في صفحة توليد الـ Feature.

"Duplicate DI registration for X found N times"

المصدر: FeatureValidator بعد التوليد، عندما يجد أكثر من سطر registerLazySingleton<X> لنفس الصنف في service_locator.dart. هذا خطأ حقيقي (رمز الخروج 1)، وليس تحذيرًا — لأنه يعني عادةً تعديلًا يدويًا سابقًا تعارض مع التسجيل التلقائي.

الحل: افتح service_locator.dart واحذف السطر المكرَّر يدويًا، مع إبقاء تعليقَي الترسيخ سليمَين.
