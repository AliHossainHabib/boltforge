الأداة

إنشاء مشروع جديد (create)

شرح تفصيلي لخط أنابيب ProjectGenerator من أوله لآخره.

ماذا تفعل هذه العملية؟

تحوّل مجلدًا فارغًا إلى تطبيق Flutter قابل للتشغيل فورًا، بمعمارية موحّدة ونظام مصادقة كامل، عبر سبع خطوات متسلسلة يُنفّذها ProjectGenerator.generate() في lib/src/generators/project_generator.dart.

لماذا سبع خطوات منفصلة بدل خطوة واحدة؟

لأن كل خطوة قد تفشل لسبب مختلف تمامًا (Flutter غير مثبَّت، مشكلة شبكة عند pub add، خطأ في القالب نفسه، مشكلة تحليل حقيقية في الكود المولَّد). فصلها يعني أن رسالة الخطأ التي تصل للمستخدم دقيقة ومحدَّدة، بدل "حدث خطأ ما".

الخطوات السبع بالتفصيل

#الخطوةالأمر الفعلييتوقف عند الفشل؟
1إنشاء مشروع Flutterflutter create --org <org> --project-name <name> <name>نعم
2إضافة التبعياتflutter pub add flutter_bloc bloc dio get_it shared_preferencesنعم
3تطبيق المعمارية الأساسيةنسخ/توليد templates/base/ عبر FileServiceنعم
4تطبيق نظام المصادقةنسخ/توليد templates/auth/<password|otp>/نعم
5تثبيت التبعياتflutter pub getنعم
6تحليل الكودflutter analyzeنعم — هذه بوابة التحقق الرئيسية
7تشغيل الاختباراتflutter testلا (تحذير فقط)
💡 لماذا لا تتوقف الخطوة 7 عند الفشل؟

لأن اختبار وحدة فاشل لا يعني أن المشروع "مكسور" بنفس معنى فشل analyze (الذي يعني كودًا لا يُترجَم). الأداة تطبع تحذيرًا وتترك القرار للمطوّر.

الملفات المشارِكة بالضبط

  • lib/src/commands/create_command.dart — يستقبل args ويستدعي المُولِّد.
  • lib/src/generators/project_generator.dart — منطق الخطوات السبع.
  • lib/src/services/process_service.dart — تنفيذ أوامر flutter الفعلية.
  • lib/src/services/file_service.dart — تطبيق القوالب على القرص.
  • lib/src/template_engine/template_context.dart — دالة TemplateContext.forProject(...) التي تبني المتغيرات والأعلام (authPassword / authOtp).

مثال كود كامل: كيف تُبنى القيم المُمرَّرة للقالب

lib/src/template_engine/template_context.dart
factory TemplateContext.forProject({
  required String projectName,
  required String orgIdentifier,
  required bool usesPassword,
}) {
  final n = NameCase.from(projectName);
  return TemplateContext(
    variables: {
      'projectName': n.snake,
      'projectNamePascal': n.pascal,
      'projectNameCamel': n.camel,
      'projectNameKebab': n.kebab,
      'projectNameTitle': n.title,
      'orgIdentifier': orgIdentifier,
    },
    flags: {
      'authPassword': usesPassword,
      'authOtp': !usesPassword,
    },
  );
}

مثال: الاسم my_cool_app يُنتج projectNamePascal = MyCoolApp وprojectNameTitle = My Cool App (يُستخدم مباشرة كعنوان في MaterialApp(title: '{{projectNameTitle}}')).

عدّل هذه القائمة مباشرة. لاحظ أن الإصدارات لا تُحدَّد يدويًا هنا عمدًا — flutter pub add يختار إصدارًا متوافقًا مع SDK المستخدم الفعلي، بدل تجميد إصدار قد يصبح قديمًا مع الوقت.

أخطاء شائعة

الخطأالسبب المحتمل
تتوقف العملية عند "Adding required dependencies"لا يوجد اتصال إنترنت، أو تعارض إصدارات في pub.dev.
تتوقف عند "flutter analyze"عادة خطأ حقيقي في أحد ملفات templates/ — راجع تفاصيل الخطأ المطبوعة كاملة.
المشروع يُنشأ لكن بدون شاشة تسجيل دخولتحقق من قيمة --auth الممرَّرة، أو من إجابتك في السؤال التفاعلي.

معايير القبول

  • boltforge create test_app ينتج مشروعًا يمر بـ flutter analyze بدون أي مشكلة.
  • عند فشل أي خطوة من 1 إلى 6، لا تُطبع رسالة "Project created successfully!" أبدًا.
  • القيم authPassword وauthOtp متعاكستان دائمًا (لا يمكن أن تكونا true معًا أو false معًا).
