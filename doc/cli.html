boltforge
الأداة

أوامر الـ CLI

مرجع كامل لكل أمر، كل خيار، وكل رمز خروج (exit code).

ماذا تفعل هذه الطبقة؟

lib/src/cli_runner.dart يبني BoltforgeRunner extends CommandRunner<int> من حزمة package:args، ويسجّل ثلاثة أوامر: create، generate (له اسمان بديلان: g وfeature)، وdoctor.

لماذا package:args تحديدًا؟

لأنها الحزمة الرسمية من فريق Dart لبناء أدوات CLI بأسلوب Git/Flutter (أوامر فرعية + خيارات + مساعدة تلقائية + UsageException عند خيار غير صالح)، بدل كتابة محلّل args يدوي عرضة للأخطاء.

الأمر: boltforge create

lib/src/commands/create_command.dart
boltforge create <name> [--auth=password|otp] [--org=com.example] [--skip-validation]
الخيارالوصفافتراضي
--authpassword أو otp. إن غاب، تسأل الأداة تفاعليًا.—
--orgمعرّف المؤسسة العكسي المُمرَّر إلى flutter create --org.com.example
--skip-validationتخطي flutter analyze وflutter test بعد التوليد.false

الأمر: boltforge generate

lib/src/commands/generate_command.dart
boltforge generate <feature_name>
# أو: boltforge g <feature_name>
# أو: boltforge feature <feature_name>

يجب تشغيله من داخل جذر مشروع Flutter (حيث يوجد pubspec.yaml وlib/).

يولّد الملفات تحت lib/features/<name>/، ثم يسجّل الـ Repository تلقائيًا في lib/core/di/service_locator.dart، ثم يتحقق من النتيجة — التفاصيل الكاملة في صفحة توليد الـ Feature.

الكودالمعنى
0تم التوليد بنجاح (حتى لو طُبعت تحذيرات DI)، أو تم الإلغاء بواسطة المستخدم (Cancel)
1تحقق ما بعد التوليد وجد خطأ حقيقيًا (تسجيل DI مكرَّر، ملف ناقص، placeholder غير محلول)

الأمر: boltforge doctor

lib/src/commands/doctor_command.dart
boltforge doctor

يفحص توفّر Dart وFlutter عبر flutter --version وdart --version فعليًا (وليس افتراضًا)، ويطبع رقم إصدار boltforge نفسه.

كيف تتفاعل هذه الأوامر مع بعضها؟

كل أمر (Command<int>) هو غلاف رفيع: يتحقق من المدخلات، ثم يفوّض كل العمل الحقيقي لكائن Generator مقابل (ProjectGenerator أو FeatureGenerator). لا يوجد منطق توليد ملفات داخل ملفات commands/ نفسها — وهذا مقصود لجعل الأوامر قابلة للاختبار بحقن كائنات وهمية (راجع صفحة الاختبارات).

كيف تُضيف أمرًا جديدًا؟

  1. أنشئ lib/src/commands/my_command.dart يمدّ Command<int>.
  2. عرّف name وdescription، وأضف الخيارات في المُنشئ عبر argParser.addOption(...).
  3. اجعل كل تبعية خارجية (ملفات، عمليات) قابلة للحقن عبر مُنشئ اختياري، تمامًا كما فعلنا مع process وworkingDirectory في CreateCommand.
  4. سجّله في lib/src/cli_runner.dart عبر addCommand(MyCommand()).
  5. اكتب اختبارًا في test/cli_commands_test.dart يستدعيه عبر CommandRunner<int> مباشرة (بدون Process حقيقي).

أخطاء شائعة

✖ خطأ شائع

استدعاء ProcessService() مباشرة داخل جسم الأمر بدل جعله معاملًا قابلًا للحقن — هذا يمنع كتابة أي اختبار موثوق للأمر لاحقًا. جميع أوامر boltforge الحالية تتفادى هذا (راجع الحقل process في CreateCommand).

معايير القبول

  • boltforge --help يعرض الأوامر الثلاثة بوصفها الصحيح.
  • boltforge create بدون اسم يُرجع الكود 64 برسالة واضحة.
  • boltforge generate offer خارج مشروع Flutter يُرجع الكود 65.
